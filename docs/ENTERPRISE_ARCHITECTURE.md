# 企业级架构说明

## 当前可运行闭环

工位上传标签图片后，服务先校验真实图片内容、格式、尺寸和像素上限，再调用可插拔 OCR，随后按带版本的产品型号规则执行序列号唯一性、订单型号/批次、二维码一致性、RoHS、置信度和图像质量检查。系统给出自动放行、人工复核或拒绝，并保存原始证据、结构化字段、工位、耗时、原因码和审计事件。真实 OCR 模式使用 OpenCV 计算模糊、曝光和对比度，并直接解码二维码。

## 生产演进路径

1. 将 SQLite 替换为 PostgreSQL，并使用 Alembic 管理数据库迁移；图片迁移到 MinIO/S3，保存不可变对象版本和校验和。
2. 用企业 OIDC/LDAP 替换本地演示账号，接入组织、工厂、产线级数据权限。
3. OCR 推理拆为独立服务，通过消息队列异步削峰；质检请求继续使用幂等键防止设备重试造成重复记录。
4. Prometheus 抓取 `/metrics`，集中采集结构化日志和请求 ID，配置错误率、积压量、OCR 时延和重复序列号告警。
5. 对接 MES 获取工单，对接 QMS 创建不合格单，对接 ERP/WMS 执行冻结或放行；当前已经实现事务型 Outbox、待投递查询和幂等确认接口，现场连接器在此基础上完成签名、重试和目标系统协议转换。
6. 配置数据库备份、对象存储生命周期、灾备演练、审计留存周期和序列号数据脱敏策略。

当前仓库已提供 SQLite 在线一致性备份、完整性校验、SHA-256 校验文件和轮换脚本；跨节点灾备仍需在目标企业基础设施中落地。
